# 自定义编译器兼容性

适用版本：1.0.0-rc.1。核验日期：2026-11-09。

## 实测结果

以下四套真实工具链均在加入中英界面与紧凑工具栏后的最终发布包上完成 16 组功能验证。测试在 Windows/Linux 原生应用中设置独立编译器路径，通过编辑器保存源码，按 F9 编译，确认实际执行的命令使用所选 C/C++ 编译器。送测、导出和部分调试步骤通过应用 IPC 驱动，终端文本按 Xterm 的实际显示检查。

| 平台 | 工具链 | 结果 |
| --- | --- | --- |
| Linux x64 | GCC 13.3.0 | 16/16 |
| Linux x64 | Clang 18.1.3 | 16/16 |
| Windows x64 | GCC 14.2.0 / MinGW-w64 UCRT | 16/16 |
| Windows x64 | Clang 19.1.7 / MinGW-w64 UCRT | 16/16 |

输出超限测试使用 3 秒时限及 4 KiB 输出上限，分开检查输出限制与启动速度。早先 Windows 的 500 毫秒测试先触发 TLE；同一源码、同一已编译程序在更长时限下返回 OLE。

## Windows 安装路径

使用 [WinLibs 的 GCC/Clang UCRT 发行包](https://github.com/brechtsanders/winlibs_mingw/releases/tag/14.2.0posix-12.0.0-ucrt-r3)，核对发布方 SHA-512 后解压测试。

- 含中文的安装路径：GCC 无法定位真实存在的启动对象文件，Clang 链接退出。脱离 LabPad 使用相同命令也失败；仅换成英文目录别名仍失败。
- 将同一套工具链实际移到英文目录后：两者编译、运行恢复；编译器文件哈希一致。完整矩阵使用含空格的英文安装路径。
- 中文项目名称、中文源码文件名、中文输入输出另行实测正常。错误诊断中的中文源码路径为有效 UTF-8。

建议把独立工具链解压到 C:\Tools\mingw64 一类简短英文目录，再在设置中选择 bin 下的 C 和 C++ 编译器。这一安装路径限制出现在本轮实测的 WinLibs 发行包。

## 本轮修复

单文件命令原先总在源码后追加 -x none，Clang 会报告多余参数；加入 -Werror 后会让正常程序编译失败。现复用参数解析，仅在后面还有对象文件等输入时重置语言。实际回归同时验证分写的库参数与外部对象文件链接，细节见 [源码审查 R12](audit-report.md)。

## 核验边界与复跑

自定义编译器必须具有目标平台所需的头文件、链接器和运行库，并与本机架构匹配。当前矩阵覆盖 GNU/Linux 与 MinGW-w64 目标；macOS 自定义编译器没有实机验证。

仓库入口为 pad/tests/ui/rc1-toolchains.spec.ts。LABPAD_TEST_TOOLCHAINS 传入工具链数组，每项包含 name、kind、cPath、cppPath；kind 为 gcc 或 clang。使用实际打包程序运行，保持每套工具链独立数据目录。原始安装路径失败、命令对照与首轮日志保存在 .work/rc1-final-audit；最终发布包复验日志为 .work/rc1-localization/release-toolchains-linux.log 和 release-toolchains-windows.log。
